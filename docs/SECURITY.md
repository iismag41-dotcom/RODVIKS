# Безопасность RODVIKS

## Реализовано

- **Пароли**: Argon2 (argon2, стандартные параметры). Хеши и пароли никогда не покидают backend.
- **Аутентификация**: JWT (HS256), Bearer-токен, срок 7 дней (настраивается `JWT_EXPIRES_IN`). Проверка на каждом защищённом маршруте REST и при каждом Socket.IO-подключении.
- **Авторизация чатов**: проверка членства (ChatMember) на каждый запрос истории/отправки — и REST, и Socket.IO-события (`message:send`, `typing`, `messages:read`, `chat:join`).
- **Валидация**: Zod на всех входных body (username/email/пароль/тексты — длины, форматы, наборы символов).
- **Rate limiting**: 20 попыток / 15 мин на `/auth/*`; 300 запросов / мин на `/users`, `/chats`, `/media` (по IP).
- **Загрузка файлов**: только изображения (расширение + MIME-тип), лимит 10 МБ, имя = случайный UUID (исключает path traversal), каталог вне кода.
- **Секреты**: только `.env` (`.gitignore`), в production отсутствие `JWT_SECRET` — ошибка запуска.
- **SQL-инъекции**: исключены (Prisma — параметризованные запросы).

## Известные ограничения MVP (задокументировано осознанно)

1. **JWT хранится в DataStore без шифрования.** При физическом доступе к рутированному устройству токен извлекаем. Улучшение: EncryptedSharedPreferences / Keystore.
2. **`/uploads` отдаёт файлы без авторизации.** Имена — случайные UUIDv4 (неугадываемы), но ссылку можно передать. Улучшение: signed URLs или проверка токена.
3. **`usesCleartextTraffic=true`** (HTTP без TLS) — нужно для локальной разработки. Для продакшена: reverse-proxy с TLS (nginx/Caddy) и `https://` в приложении.
4. **Нет refresh-токенов**: по истечении 7 дней — повторный вход.
5. **Multer 1.x**: npm предупреждает об известных CVE в 1.x. Функционально работает; план — миграция на multer 2.x (API совместим, но требует перезапуска сервера и проверки).
6. **Socket.IO CORS** в dev — `*`. В production (`NODE_ENV=production`) запрещён.

## Рекомендации для продакшена

- Всегда HTTPS за reverse-proxy (nginx + Let's Encrypt или Caddy с автосертификатами).
- Отдельный сильный `JWT_SECRET` (32+ случайных байт), ротация.
- Регулярные бэкапы PostgreSQL: `pg_dump rodviks > backup.sql`.
- Ограничить доступ к БД (не открывать 5432 наружу, слушать localhost).
- Ограничить размер `uploads/` и чистить осиротевшие файлы.
